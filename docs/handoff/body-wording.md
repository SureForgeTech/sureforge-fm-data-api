## Summary

The private preview's form said "registration" for a form that is not one, so a user who drafted a **Feedback or Request Form** read "registration" in the browser. The previewed form, the runtime's 404 body and the extension's two FileMaker-saves messages now talk about the **submission** the user is making.

## Linked issue

Closes #577

## Changes

- The previewed form's messages, its error heading and its legend name the submission instead of a registration.
- The runtime's 404 body and the adapter's rejected-submission message name the form instead of a registration.
- The extension's two FileMaker-saves messages name the app and the source layout instead of a registration.
- Say at the two places where a reader might be tempted to "fix" the name that the session-storage key and the bridge route are state and protocol rather than wording, and leave them alone.

## Test plan

The full repository gate passed on the reviewed head `a09396721744d2a7f934391682779542ab6da5f1`, in the order of the `build-test` job: `npm ci`, `npm audit --omit=dev --audit-level=high` (0 vulnerabilities), `npm run lint`, the workflow regression tests, the shared build, `npm run mock:check -w extension` (67/67), `npm run typecheck`, `npm run test:coverage` (301 files, 5,925 passed, 21 skipped), `npm run build`, `npm test -w designer-ui -w runtime-next` (230 passed) and `npm run package:check`; the VSIX was 2,896,774 bytes against the 3 MiB budget.

The sandbox exports `HTTP_PROXY`/`HTTPS_PROXY`, which the extension's TLS code reads as "a proxy is configured on this computer" and fails closed on. That changes the outcome of 26 proxy-sensitive TLS unit tests, so the gate unsets the proxy variables for the test steps, as the hosted runners have no proxy. The same 26 failures were reproduced on unmodified `main` in this sandbox before any change was made.

The runtime's own suite is green: 19 files, 232 tests. The one test that asserted the old success text now asserts the new one.

These three runtime files carry no `fmweb-managed` marker and are not in the extension's `MANAGED_TEMPLATE_FILES`, `SHIPPED_MARKED_HASHES` or `SHIPPED_SHARED_HASHES`, so no template version bump and no hash entry are owed, and the change reaches newly generated apps; an app generated by an earlier extension version keeps its old copy.
